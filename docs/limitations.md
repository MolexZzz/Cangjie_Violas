# 已知限制

## 实现边界

- 核心向量存储使用 `Float64`，内存占用高于常见的 Float32 向量库；
- HDMG 构图需要计算微簇之间的成对距离，时间复杂度仍为 `O(G²)`；
- rep/single 接口只记录精确遍历快照，不是 ANN 索引；
- HDMG 尚未实现序列化，每个新进程需要重新构图；
- `VectorMap` 仍承担较多职责，后续应拆分存储、索引和检索策略；
- 公开可变容器允许调用方绕过索引失效机制，直接修改后必须调用 `markDirty()`。

## 实验边界

- 已冻结的正式结果只覆盖三个图像数据集；
- COCO 使用项目确定的 10,000 张清单，不等价于 COCO 全部图片；
- 外部数据库通过 Python SDK 适配器调用，并非仓颉原生客户端；
- Windows Docker service 延迟包含通信开销，不能直接与论文的进程内延迟比较；
- 参数扫描使用每个数据集固定 200 个查询；发布默认配置另有完整查询池结果；
- 延迟数据只对当前硬件和软件环境有效。

## 结果边界

Faiss 负责 embedding 向量索引，Violas 负责 mixed semantic/embedding 检索。两者的 Recall、
NDCG、延迟和代码行数必须结合任务定义解释，不能作为相同目标函数下的直接排名。

## 后续工作

2. 增加 HDMG 序列化和增量更新；
