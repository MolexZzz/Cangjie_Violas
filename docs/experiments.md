# 实验方法与结果

## 数据与协议

实验使用 Caltech-101、CUB-200-2011 和 COCO 图像数据。图片和类别文本均由 CLIP ViT-B/32
编码为 512 维向量。每个类别按固定随机种子划分 90% 建库数据和 10% 查询数据。

所有后端读取同一冻结 artifact；训练集、查询集、微簇和 exact mixed ground truth 不由各后端
重新生成。

| 数据集 | 原始记录 | 训练向量 | 查询向量 |
| --- | ---: | ---: | ---: |
| Caltech-101 | 8,677 | 7,766 | 911 |
| CUB-200-2011 | 11,788 | 10,597 | 1,191 |
| COCO | 10,000 | 8,967 | 1,033 |

## 指标

- Recall@3：返回 Top-3 与 exact mixed Top-3 的重合比例；
- NDCG@3：以 mixed relevance 作为分级相关性；
- 查询延迟：只统计单次搜索调用，不包含数据读取和构图；
- 构建时间：从冻结微簇建立目标索引的耗时；
- 维护时间：固定 200 条记录的批量插入、更新和删除耗时。

## 全量结果

三数据集、11 个 β 值和完整 10% 查询池均已运行。β=0.5 时：

| 数据集 | Violas Recall@3 | Violas NDCG@3 | Violas 延迟（ms/query） | w/o HDMG Recall@3 |
| --- | ---: | ---: | ---: | ---: |
| Caltech-101 | 0.998536 | 0.999994 | 1.085818 | 0.998536 |
| CUB-200-2011 | 1.000000 | 1.000000 | 1.421441 | 1.000000 |
| COCO | 0.996450 | 0.999944 | 0.904350 | 0.995482 |
| 三数据集平均 | 0.998329 | 0.999979 | 1.137203 | 0.998006 |

完整 β 表和冻结 JSON 见 [results-summary](../results-summary/README.md)。

## 性能优化

Caltech 固定查询实验中，启用 `-O2`、加载时归一化并使用归一化余弦快速路径后：

| 阶段 | 优化前 | 优化后 | 加速 |
| --- | ---: | ---: | ---: |
| HDMG 查询 | 76.50 ms/query | 1.25 ms/query | 61.4× |
| HDMG 构建 | 77.6 s | 0.91 s | 约 85× |

优化前后 Recall 保持一致。该对比用于验证实现优化，不代表跨硬件的绝对性能。

## 参数扫描

参数扫描在每个完整 artifact 的固定前 200 个查询上执行，β=0.5，以 exact mixed Top-3 为真值。

| 配置 | 平均 Recall@3 | 最低 Recall@3 | 平均 NDCG@3 | 延迟（ms/query） |
| --- | ---: | ---: | ---: | ---: |
| sparse-graph | 0.993889 | 0.985000 | 0.999810 | 1.049 |
| small-candidate-pool | 0.996667 | 0.991667 | 0.999967 | 0.894 |
| paper-default | 0.998333 | 0.996667 | 0.999978 | 1.108 |
| wide-candidate-pool | 0.999444 | 0.998333 | 0.999985 | 1.520 |
| dense-graph | 0.998333 | 0.996667 | 0.999978 | 1.211 |

宽候选池获得最高准确率，但平均延迟比默认配置增加约 37%。小候选池更快，但 COCO Recall
下降。默认配置处于稳定的准确率—延迟折中点，因此发布版本不更改默认参数。

## Faiss 对比

统一 LOC 规则为“非空且去除纯注释的源码行”：

| 范围 | 源码行 |
| --- | ---: |
| 仓颉全部生产代码 | 4,504 |
| 仓颉存储核心 | 1,964 |
| Faiss CPU library | 95,298 |
| Faiss CPU + GPU | 132,769 |

Violas 与 Faiss 的检索目标不同：Violas 原生计算语义和 embedding 的 mixed objective；
Faiss 基线计算 embedding 相似度。LOC 和延迟只能在同时说明功能边界时使用。

## 结果解释

外部数据库在 Windows Docker service 模式运行，延迟包含进程间通信，不能直接视为论文中的
嵌入式数据库延迟。当前结果覆盖三个图像数据集，不是原论文六数据集平均值。
