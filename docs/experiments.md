# 实验设置

## 数据与划分

实验使用 Caltech-101、CUB-200-2011 和 COCO 图像数据。图片和类别文本均由
CLIP ViT-B/32 编码为 512 维向量。以随机种子 42 按类别划分数据，其中 90% 用于建库，
10% 用于查询。

各后端读取相同的实验输入，包括训练集、查询集、微簇和 exact mixed ground truth，
不在后端内部重新划分数据。

| 数据集 | 原始记录 | 训练向量 | 查询向量 |
| --- | ---: | ---: | ---: |
| Caltech-101 | 8,677 | 7,766 | 911 |
| CUB-200-2011 | 11,788 | 10,597 | 1,191 |
| COCO | 10,000 | 8,967 | 1,033 |

## 评价指标

Recall@3 表示返回结果与 exact mixed Top-3 的重合比例；NDCG@3 使用 mixed relevance
作为分级相关性。查询延迟只统计单次搜索调用，不包含数据读取和构图；构建时间从既定微簇
开始计时，至目标索引建立完成为止。

## 完整查询集结果

三套数据均使用完整的 10% 查询集。β=0.5 时：

| 数据集 | Violas Recall@3 | Violas NDCG@3 | Violas 延迟（ms/query） | w/o HDMG Recall@3 |
| --- | ---: | ---: | ---: | ---: |
| Caltech-101 | 0.998536 | 0.999994 | 1.085818 | 0.998536 |
| CUB-200-2011 | 1.000000 | 1.000000 | 1.421441 | 1.000000 |
| COCO | 0.996450 | 0.999944 | 0.904350 | 0.995482 |
| 三数据集平均 | 0.998329 | 0.999979 | 1.137203 | 0.998006 |

各 β 取值的完整结果和 JSON 数据见 [实验结果](../results-summary/README.md)。

## 实现优化

在 Caltech 固定查询实验中，编译优化、加载时归一化和归一化余弦快速路径带来的变化如下：

| 阶段 | 优化前 | 优化后 | 加速 |
| --- | ---: | ---: | ---: |
| HDMG 查询 | 76.50 ms/query | 1.25 ms/query | 61.4× |
| HDMG 构建 | 77.6 s | 0.91 s | 约 85× |

两次运行的 Recall 相同。该表比较的是同一实现的优化前后结果，不用于跨硬件比较。

## HDMG 参数

参数扫描在每个数据集的前 200 个查询上执行，β=0.5，以 exact mixed Top-3 为真值。

| 配置 | 平均 Recall@3 | 最低 Recall@3 | 平均 NDCG@3 | 延迟（ms/query） |
| --- | ---: | ---: | ---: | ---: |
| sparse-graph | 0.993889 | 0.985000 | 0.999810 | 1.049 |
| small-candidate-pool | 0.996667 | 0.991667 | 0.999967 | 0.894 |
| paper-default | 0.998333 | 0.996667 | 0.999978 | 1.108 |
| wide-candidate-pool | 0.999444 | 0.998333 | 0.999985 | 1.520 |
| dense-graph | 0.998333 | 0.996667 | 0.999978 | 1.211 |

`wide-candidate-pool` 的平均 Recall@3 最高，平均延迟比 `paper-default` 高约 37%；
`small-candidate-pool` 延迟最低，但 COCO 的 Recall@3 较低。综合三套数据的结果，
代码仍采用 `paper-default`。

## Faiss 代码量

代码量按去除空行和纯注释后的源码行统计：

| 范围 | 源码行 |
| --- | ---: |
| 仓颉全部生产代码 | 4,504 |
| 仓颉存储核心 | 1,964 |
| Faiss CPU library | 95,298 |
| Faiss CPU + GPU | 132,769 |

Violas 计算语义与 embedding 的混合距离，Faiss 基线只计算 embedding 相似度。因此代码量
和延迟表用于说明实现规模与运行情况，不构成相同检索目标下的性能排名。更细的模块级统计见
[Violas 与 Faiss 对比](../results-summary/faiss-comparison.md)。

## 测量条件

外部数据库在 Windows Docker service 模式下运行，延迟包含进程间通信。当前实验只覆盖
三个图像数据集，所有平均值均为这三个数据集的等权平均。
